# 桌面客户端界面检查记录

日期：2026-09-08。代码保存在当前工作区，未提交或发布。

此记录描述当天凌晨的版本。下午按用户新要求改为在登录页面加载配置、提示升级，并通过显式勾选实现延迟自动登录；最新流程与验证见 [`login-flow-review.md`](login-flow-review.md)。下文启动页、会话恢复和升级按钮默认聚焦描述仅作为历史记录；升级弹窗现已取消按钮的默认焦点，主界面也已统一使用自定义标题栏。

## 已完成的优化

- 启动时先显示无系统标题栏的品牌页面和“加载配置中…”，加载配置后在页面内显示升级提示。升级判断仍早于业务 API 探测和登录状态恢复。
- 升级弹窗采用紧凑的共享样式，空更新说明不再占用大块空间。保留用户确认的测试版本号 100；版本前的 TOPNODE、当前版本行和常驻浏览器说明均已移除。
- 启动窗口可拖动、最小化、关闭；进入登录/主界面时沿用启动窗口位置。
- 退出登录和重置订阅的遮罩覆盖整个内容窗口，包括侧栏和页面留白；点击背景不会穿透触发导航。
- 升级、退出、重置弹窗默认聚焦安全选项，Tab 在弹窗内循环；Esc 可取消普通确认，不能跳过强制升级。
- 按钮、侧栏导航、连接模式选项、设置开关增加可见键盘焦点和辅助功能语义。主按钮统一纯色，避免兼容渲染下渐变圆角显示异常。
- Windows 默认使用 Winit 软件渲染；显式设置 `SLINT_BACKEND` 时仍尊重该选择。实测原 GPU 路径在本机原生截图中出现透明/空白窗口，软件渲染路径能够正常显示和捕获；尚不能区分前者是窗口合成还是捕获兼容性问题。
- 已核对邮箱占位文字、个人中心下方的“关于我们”、官网与手动更新入口、两种模式下的 UDP 说明，以及深浅背景下的小尺寸托盘图标。
- 已保留此前实现：节点选择不跨启动恢复；下载地址优先匹配当前构建架构的 `downloads`，再使用 `download` 兜底。

## 实际程序验证

从最终构建目录启动 Windows 程序，使用原生窗口自动化查看截图、焦点与控件状态：

- 线上配置能触发版本 100 的启动升级提示。
- Tab / Shift+Tab 在“稍后再说”和“立即升级”之间循环。
- Esc 跳过可选升级后进入登录页；邮箱提示为“请输入邮箱”。
- 拖动启动窗口后，主窗口保持相同位置（可见边缘存在原生窗口边框差异）。
- 最终构建最小化后，重复启动恢复同一个窗口，保持单实例；最终登录按钮圆角正常。
- 关闭启动页能结束启动；关闭主窗口仍按现有设计隐藏至托盘。

登录后的页面、强制升级、错误/重试、退出及订阅重置使用相同 Slint 组件的本地预览数据验证。没有输入真实账户密码、重置真实订阅、建立代理连接、安装更新或修改线上配置。官网按钮的实际外部浏览器跳转未在登录后的真实会话内重测。
